> **一个突如其来的需求**
我们经常会面临着一个突然的需求，就是我们需要在DOM 绑定一个函数，并且这个函数是事先预定好的（提前写好了的），因为这种方式可以很方便我们去维护代码。

接下来是一个最简单的函数绑定
```javascript
        var oBtn = document.getElementById("btn");
        // 函数绑定缘起缘灭，有的时候我们想在一个函数中调用另一个函数
        var handle = {
            message: "事件被处理了",
            handler: function (event) {
                alert(this.message);
            }
        }
        // 把handle里的事件绑定到按钮的click事件中，结果undefined
        oBtn.addEventListener("click", handle.handler, false);
```
为什么会出现undefined？显然是哪里出了问题。熟悉闭包的人，一眼就看出问题所在了。因为handle.handler这个函数的执行环境变了，或者换句话说，我们没有保存这个执行环境，此时的this指向的是oBtn这个DOM元素而不是handle，那么我们该怎么去做。
最简易的写法，直接写一个闭包，然后在闭包函数中立马执行handle.handler这个函数。
```javascript
        oBtn.addEventListener("click",function (event) {
            handle.handler();
        })
```
显然这个方法只是特例，不具有普遍性。那么我们是否可以单独提出一个函数，专门用来用来保存函数执行环境，答案是必须可以的。
```javascript
        // 接下来我们改写一下
        function bind(fn, context) {
            return function () {
                return fn.apply(context, arguments);
            }
        }
```
我们写一个bind函数，fn是要绑定的函数，context是执行环境（一般情况是一个对象，也就是绑定函数的实例）；调用apply的方法，把context这个执行环境绑定到fn，并且传入fn的arguments，事情就迎刃而解。然后我们在利用bind函数把这个函数绑定到DOM中；
```javascript
oBtn.addEventListener("click",bind(handle.handler,handle),false);
```
方法看上去十分简单，但是这确实无数前端大师，大神总结出来的最切实可行的方法，我们站在巨人的肩膀上，用的貌似理所当然，但要怀着一颗感恩的心，当然也要懂得去分享；
同时，这个方法虽然简易并且切实可行，但是不建议总是使用，因为对内存的消耗远大于普通的函数；
